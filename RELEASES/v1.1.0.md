# KmerHosting Domain Portal v1.1.0

Release date: 2026-07-26

## Summary

This release moves the platform from test-oriented setup to production-ready configuration for the KmerHosting domain portal, while keeping provider safety checks active.

## Production mode

- DomainNameAPI registrar environment switched to production in Supabase configuration.
- CamerPay sandbox flag disabled in Supabase configuration.
- Maintenance mode disabled in Supabase configuration.
- Public checkout banner now disappears when checkout is enabled.
- Checkout still validates DomainNameAPI `usdBalance` before creating a paid order.

## Provider safety

- DomainNameAPI balance parsing now uses the real provider field names: `usdBalance` and `tryBalance`.
- Removed internal aliasing of provider balance fields from the registrar proxy.
- `domain-order-guard` blocks checkout when `usdBalance` cannot cover the provider cost.
- Provider quote storage remains active for auditability and premium/exact price handling.

## Customer features

- Added native `/dashboard/notifications` page.
- Added native `/dashboard/domains/:domainId/manage` page.
- Added pre-action quotes for renew, transfer and restore.
- Added web forwarding GET / PUT / DELETE flow with local/provider state.
- Added glue host GET / POST / PUT / DELETE flow with local/provider state.
- Added notification read and read-all actions.

## Admin features

- Added native admin pages:
  - `/admin/provider`
  - `/admin/tlds`
  - `/admin/logs`
  - `/admin/cron`
- Added provider account and provider transaction views.
- Added provider TLD catalog view.
- Added provider logs view.
- Added cron status monitoring view.

## Automation and observability

- Instrumented domain cron invocations in `domain_cron_runs`.
- Added `domain-admin-monitor` API client integration.
- Added operational checks for failed crons and delayed order states.

## Known operational note

The platform is configured for production checkout. The backend still requires the DomainNameAPI production `usdBalance` to be sufficient before allowing real paid domain orders to proceed. If the provider balance is too low, checkout is refused before an unfulfillable order is created.

## Remaining technical debt

- TypeScript strict build is still available as `build:strict`, but the production build remains `vite build` until all strict typing issues are cleared.
- Some runtime compatibility modules are still loaded while native pages are progressively replacing them.
- Auth still uses bearer token storage on the frontend; HttpOnly cookie migration remains a future hardening task.
